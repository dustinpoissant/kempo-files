# Changelog

All notable changes to `kempo-files` are documented in this file.

## [Unreleased]

### Added

First release. A file library for kempo that stores uploads in real folders under `files/` at the site root — a sibling of `public/`, never inside it — and serves every one of them through a permission-checked route rather than the static file scanner.

- **Real directories.** Create, rename, move and delete folders, with real names on disk. Deleting a non-empty folder is refused rather than recursing, so one request cannot destroy an unbounded amount of other people's work.
- **Real filenames.** A download arrives called what it was uploaded as. Every name that becomes a path segment goes through one validator (`server/utils/names/sanitizeName.js`) that rejects traversal, control characters, Windows-reserved device names, and trailing dots or spaces — the last because Windows silently strips them, which would leave the database describing a file that is not there.
- **Collisions are refused, never silently resolved.** `fs.rename` replaces an existing destination without complaint, so every rename and move checks first. Auto-suffixing a colliding upload to `logo-1.png` would mean the file someone linked is not the file they uploaded.
- **`public` per file** — downloadable with no session at all. Permissions cannot express this on their own: `currentUserHasPermission` answers 401 the moment there is no token, so it can only ever describe which *authenticated* users may act.
- **Own/others permissions** throughout, for files and folders alike, matching the pattern already used elsewhere in kempo.
- **The `trusted` flag, in place of a banned-types list.** Untrusted source files are served as `text/plain` with `nosniff`: viewable, unexecutable. Untrusted opaque binaries are served as attachments. Only `files:upload_trusted` can approve a file, and **replacing an approved file's contents as an untrusted writer drops it back to unreviewed** — otherwise approval could be obtained once and the contents swapped afterwards.
- **Aliases.** A public file can also be served at a real-looking path (`scripts/analytics.js`) via kempo's `route:unmatched` hook, so references need not look like API calls. The alias runs the identical gate as the id URL — it is a second lookup key, never a bypass — and is cleared if the file stops being public.
- **Hooks:** `file:before_upload` and `file:before_download` (both bail-capable, for refusing an upload or vetoing a download), `file:uploaded` (notification, for scanners and thumbnail generators) and `file:deleted` (notification, carrying the deleted row, so anything derived from a file can be removed with it).
- **Range support on gated downloads.** Bytes go out through kempo-server's own file server, so a permission-checked video seeks exactly like a static one.
- **Admin library** built from kempo-ui components — `k-table` for the list view (matching every other admin screen), `k-card-grid` (kempo-ui's generic tile-grid counterpart to `k-table`) for the grid, `k-segmented-control` to switch between them, and a `k-dropdown` menu per entry. Folders, breadcrumb navigation, drag-and-drop upload, move, public and trust toggles, alias editing, and a **Needs review** filter for files awaiting approval. Grid vs list is remembered across visits via `k-segmented-control`'s own `persistent-id` (kempo-ui >= 0.4.53). `FileLibrary.js` is the orchestrator (state, data loading, drag-drop, the grid/list layouts, `renderTile` as `k-card-grid`'s `cardTemplate`); everything reusable is a sibling `k-files-*` component — `k-files-thumb` (owns its own broken-image fallback), `k-files-entry-menu`, `k-files-toolbar`, `k-files-breadcrumb`, `k-files-upload-progress`, `k-files-file-details` — matching kempo-blog's `k-blog-*` prefix convention.
- **Bulk actions**, available any time one or more rows are checked — not gated behind any filter, and identical in list and grid view. Selection count, move, make public, make private, approve, reject and delete, as a `k-files-tc-*` family (`TcSelectionCount`, `TcMoveSelected`, `TcMakePublicSelected`, `TcMakePrivateSelected`, `TcApproveSelected`, `TcRejectSelected`, `TcDeleteSelected`, in `admin/components/table-controls/`) built on kempo-ui's own `ButtonControl`/`Control` base classes — the same framework behind kempo-ui's `kc-tc-delete-selected` and kempo core's `AdminTableControl`-derived admin controls. Each discovers its host via `closest('[controlled]')` (`Control`'s own mechanism) and reads that host's live selection through its real `getSelectedRecords()`; the ones that need a server call a generic host has no business knowing about dispatch a bubbling event for `FileLibrary` to act on, the same division of labor as kempo core's `GroupDeleteSelected` → `groupRemoveSelected`. Make-public/make-private/approve/reject stay files-only (folders have no such fields) and dispatch `{ detail: { ids } }`; move and delete apply to a folder exactly as they do to a file, so those two read the full, unfiltered selection and dispatch `{ detail: { records } }` instead, letting `FileLibrary` route each record to the file or directory version of the action. **The same controls work unmodified against either host** — `k-table` in list view, `k-card-grid` in grid view — because `k-card-grid` (added to kempo-ui alongside this) implements `getSelectedRecords`/`selectAllOnPage`/`deselectAllOnPage`/`selectionChange`/`deleteSelected`/`requestDelete` identically to `k-table` and sets `controlled` on itself the same way; no kempo-files-specific branching exists anywhere in the controls themselves. `TcSelectionCount` stays visible at `0 selected` rather than hiding at zero, so the bar doesn't shift as the count's digit-width changes; there is no dedicated "Clear" control, since unchecking the host's own "Select all" already clears the selection in one click. They sit in whichever host's own `slot="top"`, always mounted once permission allows, each independently disabling itself (`willUpdate` + `hostEvents: ['selectionChange']`) while nothing eligible is checked rather than the whole strip disappearing — matching `kc-tc-delete-selected`'s own always-there-but-disabled behavior. Approve/reject only render for whoever holds `files:upload_trusted`, same as the per-file entry menu.
- **A live byte-size column.** `sizeBytes` is computed with `fs.stat` at list time rather than stored — nothing on disk can drift out of sync with what the database claims a file weighs.
- **A PDF preview in the details dialog**, for approved files only — an unapproved PDF is still served as a forced download, so there's nothing an iframe could safely render yet. Trusted-file responses add `X-Frame-Options: SAMEORIGIN` (kempo-server's own default is the stricter `DENY`, which also blocks a same-origin preview iframe) — third-party framing stays blocked, only this site's own admin preview is let through.
- **Real upload progress.** Uploads go through `XMLHttpRequest` rather than `fetch` — `fetch` has no upload-progress event, only a download-body stream — so the bar shown during upload (kempo-ui's `k-progress`) tracks actual bytes sent rather than an indeterminate spinner.
- **Per-card actions in grid view**, replacing the kebab entry-menu on file tiles — and, since this same mechanism now works for a folder exactly as it does a file, on folder tiles too, which is what finally makes a folder tile and a file tile the same shape (no more separate folder-only markup). Built on `k-card-grid`'s `slot="before"`/`slot="after"` per-tile controls (a `k-files-tc-*` family in `admin/components/table-controls/`) — the same mechanism `Table`'s own before/after row controls use: a template registered once gets cloned (tag, attributes and any static inner markup) into every tile, so a control resolves its own record by walking up to its own tile's `data-index` and reading it off the host, mirroring kempo core's `AdminTableControl.record`. Two mixins split that shared logic by what actually needs it: `CardRecordMixin` (record resolution only) and `CardControlMixin` (that, plus hiding on anything that isn't a file — used only by the two controls where that's actually true). The selection checkbox renders as the first item in the top strip rather than a separate overlay — the "before" control `k-card-grid` supplies itself. The bottom strip holds the rest: `TcToggleFilePublic`/`TcToggleFileTrusted` (file-only, via `CardControlMixin`) on the left, colored green (`tc-success`) or red (`tc-danger`) by the file's *current* state (`public`/`public_off`, `check_circle`/`cancel` — four new icons added to kempo-ui) rather than the action, matching `accessIcon`/`statusIcon`'s existing convention elsewhere — the old "Trusted"/"Unreviewed" pill on the thumbnail is gone, since the icon's color already says the same thing — and, on the right, a genuine `kc-menu` (kempo-ui's own dropdown-menu control) holding three real `ButtonControl`s, `TcRenameEntry`/`TcMoveEntry`/`TcDeleteEntry` (`CardRecordMixin`, not `CardControlMixin` — these apply to a folder exactly as they do a file), the same composition kempo-ui's own `HtmlEditor` toolbar uses (`kc-format-block` slotted into `kc-menu`) rather than a hand-rolled dropdown with plain `data-value` buttons. A plain flex-spacer div between the toggles and the menu pushes the menu to the far edge; it and the whole strip both collapse to nothing when everything inside ends up hidden for a given record (see kempo-ui's own `CardGrid` fix). Because a clone only carries attributes and static markup, never a Lit event listener, the toggle controls' events are listened for on `k-card-grid` itself rather than on the template registration — binding `@toggle-public` etc. directly on the template elements silently never fires, since the clicked element is a different node than the one the listener was attached to. The menu's three items need no such workaround: each resolves its own record and dispatches its own `rename-entry`/`move-entry`/`delete-entry` event directly, same as the toggles. List view's per-file entry menu (`k-files-entry-menu`) still has a few things the grid's menu doesn't — Details…, Open in new tab, public/alias/trust — so it stays for that view specifically rather than being retired.
- **Browser-test coverage for the whole `table-controls/` family and `EntryMenu`** (`tests/components/`) — real components against a real `k-card-grid` host, no kempo-server or database involved: kempo-ui is resolved through an import map (`/kempo-ui/` → the installed package's own `dist/`) on a custom test page, so a control's `/kempo-ui/...` imports behave exactly as they do in production without anything faked. Along the way, found and fixed two bugs in `kempo-testing-framework` itself that were blocking a custom `page` export from working for any test file that (like these) imports a browser-only absolute specifier — a Node-side import used only to detect the export was throwing on exactly those files, and the framework's own injected test-runner script was requesting the wrong path for `runTests.js`.
- **A details dialog on clicking a file** — previews images, video, audio and source text (fetched and shown as text, never executed), alongside a metadata table: path, type, access, trust status, canonical API URL, alias, owner and timestamps. The API URL is shown separately from the alias because it keeps working whatever the alias is later changed to. An unapproved file gets an **Approve** button right there next to Close, for anyone holding `files:upload_trusted` — reviewing is the whole point of opening details on something unapproved, so the action lives where the reviewing happens rather than back in the entry menu.
- **SVGs and HTML files get Preview and Source tabs**, not just a raw `<img>` or source dump. Approving either means both seeing what it renders *and* being able to check its markup for a `<script>` tag directly, rather than taking a sanitizer's word for it. Source is always the untouched bytes — the same thing an unreviewed file's own URL already shows, since both are served as `text/plain` until trusted (both can carry `<script>`). Preview strips `<script>`/`<iframe>`/`<object>`/`<embed>` elements, refresh `<meta>` tags, and `on*`/`javascript:` attributes, then renders the result through a mechanism that cannot execute scripts regardless of what the sanitizer missed — a `blob:` URL `<img>` for SVG, a script-less sandboxed `<iframe>` for HTML. Whenever the sanitizer actually finds and removes something, a warning banner says so under the Preview tab. Its own component, `k-files-visual-code-preview`.
- **Kind icons for video, audio, 3D models, archives and fonts now live in kempo core's own shared icon set** (`kempo/src/kempo/icons`), not a private copy in this extension — they're common enough that other extensions plausibly want them too. Everything else reuses kempo-ui's existing icons.
- **An alias must end with the file's own name.** The directory part is the user's to choose; the filename is not. Otherwise a `.js` could be published as `photo.png`, leaving the extension a browser reads to decide how to treat the response disagreeing with the file being served. Renaming a file carries its alias along, so the rule cannot strand one.
- **Editor integration** via `window.kempo.openAssetPicker`, which both kempo-ui's HTML editor (`kc-insert-image`) and Markdown editor (`kc-md-image`) look for — so inserting a file works in pages, templates and blog posts alike.

### Requires

- `kempo-server >= 3.3.0` for the public `serve-static-file` export.
- `kempo >= 4.2.26` for the video/audio/model3d/archive/font icons in its shared icon set. `kempo` with `route:unmatched` support for aliases. Everything else works without it.
- `kempo-ui` with `CardGrid` and the `Dropdown`/`Table` fixes described in kempo-ui's own CHANGELOG (both added alongside this release) — `CardGrid` for the grid view itself, and the `Dropdown` fix for the per-card actions menu (built on kempo-ui's own `kc-menu`) to open, close and keyboard-navigate correctly with real `ButtonControl` items instead of plain buttons.
